## ceiling

No alcanzado. El atrio y el vidrio ocupan más superficie que la identidad de las personas y los textos que la app realmente entrega. Con el nombre tapado, el primer viewport se recuerda como seis miniaturas del mismo globo, no como un muro de conversaciones distinguibles. La solución no es producir veinte portadas diferentes: la API trae texto, autores y comentarios, y esa es la materia del producto.

La API ya permite una experiencia más rica sin inventar fechas, fotos, categorías, likes o actividad: relacionar post.userId con el nombre real de muestra; filtrar por esa persona; leer title/body completos; abrir comentarios con email/body y su estado propio; compartir el contenido real. El autor puede tener iniciales derivadas del nombre y un color estable, con Usuario N como fallback. Una consulta o fallo de autor no debe impedir leer posts. La escritura debe identificar al autor de ejemplo y cerrar su recorrido mostrando qué respondió la API y qué efecto tiene en la sesión.

Quedan dispositivos de diseño útiles: filas de lectura abiertas, ritmo entre autor y título, campos con foco claro, transiciones que conservan la identidad del elemento, feedback dentro de la acción y recuperaciones pequeñas. Eso aporta gracia vinculada al uso. Más ilustración repetida, animaciones dispersas o una nueva paleta dejarían intacto el problema.
